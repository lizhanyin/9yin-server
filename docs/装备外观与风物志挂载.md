## 一、装备外观挂载（V2）

| 环节 | 实现 |
|---|---|
| 槽位口径 | `AppearanceSync`：1帽/3衣/4裤/6腕/7腿/8鞋/22武器（role_equip_items 实测）；身份装/时装 16-19、新面板镜像 40-43（GM 面板口径） |
| 登录外观合并 | `LoginFlow.onChooseRole`：`AppearanceSync.mergeVisual` 用已穿衣/裤/鞋装备的模型覆盖创角初始装，addObject 归档即带装备外形——重登不回落「初始屌丝装」 |
| 帽/时装补帧 | `pushEquipAppearance`：addObject 后 0x10 推 Hat + FashionCoat/FashionHat/FashionShoes（addObject 的 Hat 位是发型别名，F 抓包方言）；无帽/无时装零帧（帧序对齐 golden） |
| 武器外观 | 登录走 `InventoryMessages.weaponModeOf`（既有）；GM 穿戴后随 `AppearanceSync.appearanceFrame` 实时重推 WeaponMode |
| GM 发放/穿戴 | `grant_item`/`add_item {itemConfig, amount, wearNow}`：wearNow=1 写 role_equip_items + 纸娃娃行（时装镜像 40-43 双行）+ 外观 0x10 + 词缀重算（`recomputeEquipBonuses`）+ vital；否则找空槽入 role_bag_items + 成对 `0x19→0x18→0x19(镜像页)` 帧 |
| 模板生成 | `gm_generate_weapon{weaponType∈101-108/122, crafter∈cook/smith}` / `gm_generate_armor{armorSlot}`：weaponType 按模型前缀映射（blade_/sword_/thorn_/sblade_/ssword_/sthorn_/lstuff_/cosh_/claymore_），品质窗口随机挑模板 + EquipAffixCatalog 随机词条（厨师 6 / 铁匠 3 / 防具 3），复用穿戴路径 |
| 物品目录 | `ToolItemCatalog`：equipment.ini + tool_item.ini 合并（GBK），configId 大小写不敏感；`ResourceCache.text` 缓存键含 charset（同一 ini 的 Latin-1/GBK 双读法不再互相污染） |
| DB 写方法 | `RoleInventoryStore.upsertEquip/deleteEquip/insertBagItem`（affixes 列缺失自动降级，对齐读路径）；`activateFashionSuits/fashionSuits`（role_fashion_suits） |

## 二、风物志皮肤挂载（V3）

**游戏内真实流程**：卡片道具（`card_item_*`，script=CardItem，`CardID` 字段直连皮肤号）在背包 → **使用后收录**进风物志（衣橱）→ 在衣橱里**换装**。服务端两条上行链路 + GM 直通链路都已实现：

| 环节 | 实现 |
|---|---|
| 数据源 | `SkinCatalog`：客户端资源 `rule/card.ini`（1239 张：Weapon 348 / Cloth 247 / Hat 133 / Waist 101 / Cloak 57 / Mount 31 …），ModelData=`部件,模型;部件,模型` 多段；Latin-1 无损读 |
| 卡片 ↔ 皮肤映射 | `ToolItemCatalog`：tool_item.ini `[card_item_*].CardID`（如 card_item_10001↔皮肤1 屠龙刀鞘）；`cardItemBySkinId(skinId)` 反查 |
| **使用收录（C2S 30）** | `handleBagItemUse`：引擎原生穿脱/使用信封（布局无抓包，整型载荷全量记录供校准）；载荷 (view,slot) 对命中背包 CardItem → `consumeBagItem` 消耗 1 张（减量重推行/删行+镜像清位）→ 收录（不自动挂载） |
| **衣橱换装（C2S 180）** | `handleWardrobeCard`（`custom_card(int,...)`）：按皮肤当前状态幂等推进——未收录→收录（背包有对应卡片则消耗）；已收录未挂载→挂载（**同部件互斥替换**：武器换武器/衣服换衣服，发型等异部件叠加）；已挂载→卸下 |
| 状态存档 | `SkinStore`：data/skins.json 主档 + MySQL `role_skins`（admin/sql/0006 迁移；attachDatabase 建表兜底）双源，CustomizingStore 同款 |
| 协议帧 | `SkinMessages`：收集 = `CardRec[3]` 位图（32 皮肤/行，显式行号 0x11）；挂载 = `UseCardRec[2,2]`（皮肤号 + 显示类型 0）追加行、0x12 倒序删行；显示开关 = `ShowEquipType`(408,byte=2) + `CardID` 属性帧；刷新 = custom 180 |
| 整刷方言 | 增量更新先删旧行再整刷（追加方言下重推会追加成新行）；`skinRefreshFrames` 统一编排：清位图行 → 推位图 → 清挂载行 → 推挂载 → 显示开关 → on_card_msg |
| GM 直通 | `equip_card{cardId}`（未收录自动补收录+挂载）、`unequip_card`（清挂载留图鉴）、`grant_all_cards`（全量收录）——GM 网页直接挂载，不用点背包收集（F 服口径） |
| 登录恢复 | ClientReady 链（键位推送后）：`pushSavedSkins` 推已存收集位图 + 挂载行 + ShowEquipType；无存档零帧 |
| 时装页签 | `grant_all_fashion`：全部 `EquipType=FashionCoat`（525 套）→ role_fashion_suits + `FashionSuitRec` 行（登录恢复同推）+ data/新版服装数据.json 存档 |

## 四、真机校准点（无官方抓包，按 GM 面板口径实现）

1. **C2S 30 / C2S 180 载荷布局**：两处理器均整型全量记录（`custom 30 use/wear args=[…]` / `custom 180 card args=[…]`）——真机点一次卡片/衣橱即可从日志钉死 (op,view,slot,skinId) 布局，再回头把状态机换成显式子操作分发。
2. `UseCardRec` 第二列语义（暂发 0）；装备武器卡后看人物手模是否变化，不动则试发 subtype。
3. 运行时 0x10 推 Cloth/Pants/Shoes 是否热刷新；不刷新改走 `Fashion*` 通道。
4. 时装槽 16-19 与类型的对应（暂定 16=Suit / 17=FashionCoat / 18=FashionHat / 19=FashionShoes）。
5. `FashionSuitRec [7,3,3,4,3,3]` 数值列语义（暂零填充）。
   以上均为单点常量/单方法内可改。
