# 官服怒气(SP)回复 · 逐阶段帧取证

数据源：参考服抓包 `9yin_server1\captures\local\127-0-0-1-55866`（君子堂 CS_jh_myjf 族，11-04）+ `bak\127-0-0-1-52795`（hyjf 武技，11-03）。
工具：`tools/smoke/rage_stage_frames.py`（本文件结论的可复现入口）；时间轴用 msg294 对钟帧锚定（每秒一发 `[uptime_ms, tick, unix_s, …]`，全程 122 间隔恒 1000ms）。

**勘误**：combat-traffic-compare.md §4.2 旧结论「myjf08 消耗=清空整条(100→0)、+5/s 回复」中"清空"是误读——那两次 100→0 全部是**格挡清怒**，与出招无关。真消耗是 **−50**。见 §4 修正。

## 1. 总模型

SP 在 0x09 属性表 idx=**467**，type 3（i32）。官方只用两种帧形承载 SP 变更：

| 形态 | 帧型 | 结构 | 触发 |
|---|---|---|---|
| 单属性帧 18B | 0x10 | `[10 00][oid u32][owner u32][01 00][d3 01][i32 值]` | 纯 SP 事件：格挡清怒、被击+2、wuji 每跳扣 |
| vitals 大批 ~1.3KB | 0x10 | n=186/188：`LogicState, HPRatio, MPRatio, MaxHP, MaxMP, HP, MP, Speed…, SP(467), InParry(471), BufferInfo11…` | ①回复 tick ②出招/扣MP/怒招消耗等事件（批内带其它变更） |

判断规律：**只有 SP 单独变→单帧；批内还有别的 vitals 变（或 tick 到点）→大批**。MaxSP(580)/MaxSPAdd(583) 不在恢复批里（上限不随批下发）。

## 2. 满值静止（SP=100，无回复进行）

- 登录整推（#20/#28/#31 三连批）带 SP=100 之后，**零 SP 帧**。
- 1s tick 在满值期**停发**（55866 从 u=10115 到 17089 无任何批；52795 #3362 满值后只剩事件触发的 Δ+0 批）。
- 客户端满值球满、无灰化问题，官方不推任何维持帧。

## 3. 格挡清怒（msg54 手动格挡 ON）

55866 四次 SP→0（#1769/#2370/#3216/#3911）全部同构：

```
#1769 0x10 单帧 SP=0                        ← 任意当前值→0（本例 100，#3216 是 90 也清 0）
#1787 msg169 [0,'BuffInParry',玩家…]          ← 先移除
#1788 0x10 小批 {InParry=1, InManualParry=1, BufferInfo11='11CE,11000001,7A5C0B,1,C38D…,1'}
#1810 msg169 [1,'BuffInParry',玩家…]          ← 再添加
#1790 (下一秒网格) 0x10 大批 n=188 SP=5       ← 回复立即从下个 tick 起
```

单帧字节样例：`1000010000110b5c7a000100d30100000000`。
注：这与 manual-parry-msg54 已实现的「状态变化回 msg169+0x10」同族，官方额外多推 **SP=0 单帧**。

## 4. 怒招消耗（myjf08 出招）

真消耗不是清空：

| 帧 | u(ms) | SP | Δ | 形态 |
|---|---|---|---|---|
| #2597 | 56102 | 65→**15** | **−50** | 事件触发大批（伴随 MP 扣除/出招） |
| #4026 | 102102 | 55→**5** | **−50** | 同上 |

- 消耗走**大批**（非单帧），出招瞬间即推，不等 tick。
- 下一网格 tick 照常 +5（#2604 u=56108 SP=20）——净效果首秒 −45。
- 52795 四次消耗（#2227/#2965/#3698/#4110…）全部 100→50，同构。

## 5. 回复期（SP<100，1s tick）

- **每 1000ms 一帧 n=186/188 大批，SP 恒 +5**；0→100 恰 20 tick / 20 秒。
- tick 相位锁死在 msg294 对钟网格（294 在 x107，tick 批在 x108–x110，同一服务器秒栅格；不随消耗时刻重置相位）。
- **与战斗状态无关**：LogicState=0（未进战/脱战）期间照样 +5（55866 #1790–#1975 全程 0；52795 #3314–#3362、#4773–#4878 LogicState=0 仍在涨）。
- 出招扣 MP 等事件会在网格间**加推 Δ+0 批**（如 #1971/#2281/#3373/#3606：SP 不变、MPRatio 变）。
- **到 100 即停**：满值后不再有批（直到下个事件），无"到满通知帧"。

## 6. 命中驱动增量（wuji 战斗，52795 #10860+ 区段）

- 被击得怒：`msg24 [24, obj(玩家), 10, n]`（**4 值短形态**，10 是子类型非伤害）+ 紧随**单帧 SP+2**。
- wuji（hyjf08）每跳扣：打中怪后**单帧 SP −10/−5**（连跳间隔内连发）。
- NPC 实伤命中（msg24 c1=7 九值形态，两服共 17 次）**不给 SP**——不要把 c1=7 当回怒事件。

## 7. 伴随帧（非 SP 但同阶段必现）

| 帧 | 节奏 | 说明 |
|---|---|---|
| msg294 对钟 | 恒 1s | `[uptime, tick(步进1000), unix_s, 坐标?]`；回复 tick 的相位基准 |
| 0x38 hb 应答 | ~1s | 回显客户端 0x18 ping（uptime+seq） |
| CanUse=1 ×17 心跳簇 | 2–5s/簇 | 0x10 单帧 u8 idx=**2236**，对象=快捷栏槽 `obj(0x28, 1..17)`，**恒 1**（本会话 1632 帧无一 0）；首簇与格挡清怒同刻起（u=18111）。SP=0 期间照样推 1 → **客户端按 SP 本地灰化，服务端不替它算** |
| 0x11 cooldown_rec | 出招时 | 个人 CD+GCD 行，与 SP 无关但同窗 |
| 0x10 小批 QingGong 族 | ~1s | `{QingGongPoint,GJQingGongPoint,…}` 独立心跳，勿与 vitals 批混淆 |

## 8. 对 Java 实现的对齐要点

1. −50 消耗（Java 现行语义对，旧 D5 表格"参考服=清空"作废）。
2. 回复 = 服务端 1s tick +5（对齐 294 网格），**不依赖战斗态**；满值停推。
3. 格挡 ON 必须补推 SP=0 单帧（当前格挡链只推 InParry/InManualParry 批+169）。
4. tick/事件走 n≈186/188 vitals 大批（castVitalUpdate 瘦集），纯 SP 事件才用 18B 单帧——被击+2/wuji 扣勿塞进批外另造帧型。
5. CanUse 心跳簇恒 1 即可，SP 灰化交给客户端。
